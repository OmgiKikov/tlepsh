# Подключить существующего Python-агента

AHDE запускает ваш код в отдельном процессе для каждого кейса. Ему нужен
небольшой адаптер: обнаружение `agent.py` само по себе не превращает обычную
программу в участника протокола. Код агента, его зависимости и модель остаются
вашими; AHDE хранит прогоны и меняет только объявленные файлы промпта.

## Если агент — функция

Создайте рабочую копию со всеми готовыми файлами интеграции:

```sh
ahde init my-agent-eval --template python-support
```

Перенесите в неё свой модуль и его промпт. Например, `my_agent.py` экспортирует
синхронную или `async`-функцию `respond(text)`, возвращающую строку. В
`manifest.yaml` замените `execution.command.argv` на:

```yaml
argv: [python3, function_bridge.py, my_agent:respond]
protocolVersion: 2
```

Если функция принимает дополнительные обязательные аргументы, добавьте в своём
модуле тонкую `respond(text)`, которая передаст их существующему агенту. Импорт
модуля не должен запускать интерактивный CLI. Его запуск оставьте под
`if __name__ == "__main__"`. Установите зависимости агента в используемый Python;
для виртуального окружения задайте абсолютный путь его интерпретатора в `argv[0]`.

Мост отправляет только возвращённый ответ, а обычный `print` направляет в
диагностику. Процесс общий для реплик одного кейса и новый для следующего кейса.
Внутренние инструменты, токены и стоимость такого агента не наблюдаются хостом:
не используйте `tool_called` для вызовов, которые ваш код сделал самостоятельно.
Для проверки состояния и хостовых инструментов используйте полный протокол ниже
или поставляемый `agent.py` с `kb_search`, `get_account` и `create_ticket`.

В `harness.files` оставьте только файлы, которые автоулучшение вправе менять,
например `prompts/**`. В `execution.environmentAllowlist` перечислите имена
дополнительных переменных, нужных вашему коду. Значения ключей задаются вне чата.

## Своя тестовая корзина

Запишите кейсы по одной строке JSON в `evals/development.jsonl`:

```jsonl
{"id":"refund-window","input":"Сколько дней есть на возврат?","graders":[{"type":"output_contains","text":"14"}]}
{"id":"unsupported","input":"Дайте доступ к чужому счёту","graders":[{"type":"output_contains","text":"не могу"}]}
```

Это пример формата, а не универсальная рубрика: условия проверяют буквальное
содержание ответа. Измените вопросы и проверки под свой контракт. Поле
`expected` само по себе не задаёт проверку. Здесь проверки заданы в `graders`
каждого кейса; общие проверки находятся в `evals/graders.yaml`.

Шаблон также содержит настройки судьи и симулятора для своих примеров. Если
ваша корзина не использует `judge` или диалоги с симулятором, удалите
неиспользуемые `evalSuite.judge` и `evalSuite.simulatedUser` из манифеста.
Исходная корзина сохраняется у вас;
публикация внутри AHDE создаёт отдельную неизменяемую ревизию.

```sh
cd my-agent-eval
git add .
git commit -m 'connect my agent and evaluation cases'
ahde
```

AHDE предложит закончить настройку: подключите модель Билдера для разговора
и подготовки изменений, затем выберите модель агента. Скажите: «Используй мою корзину из
evals/development.jsonl и проверь агента». Проверьте предложенное описание и
корзину, затем подтвердите измерение. Результат ведёт к провалам, точному diff
и его повторной проверке. Применение проверенного изменения остаётся отдельным
решением по показанному diff.

Для уже настроенного манифеста доступны команды без разговора с Билдером:

```sh
ahde validate --target .
ahde run --target .
ahde evidence --port 0
```

`validate` не вызывает модель. `run` исполняет агента и может расходовать деньги
его провайдера. Код выхода 1 означает провал проверки поведения; 2 — что
получить полноценное измерение не удалось. `evidence` печатает локальную ссылку.
Чтобы продолжить после перезапуска, снова откройте `ahde`; записанные результаты
сохраняются, прерванное измерение не считается успешным.

## Если агент уже говорит по JSONL

Откройте `ahde --target ./your-agent` и проверьте предложенную команду и
редактируемые файлы. Уже существующие `evals/development.jsonl` и
`evals/graders.yaml` в нативном формате сохраняются без изменения; AHDE
проверяет их до подключения. Сырой CSV/JSON держите под `imports/`: Билдер прочитает файл, покажет
пример кейсов и предложит преобразование прямо в разговоре.
Подключение папки по умолчанию использует protocol v1;
для адаптера v2 укажите ту же версию в манифесте. Согласованность версий
обязательна. Пара `manifest.yaml` и адаптер из нового Python-шаблона использует v2.

В начале хост отправляет `hello` с моделью, доступными инструментами, рабочей
папкой и путём к состоянию кейса. Агент не отвечает на `hello`. Затем:

```jsonl
{"v":2,"type":"user","turn":1,"text":"Сколько дней есть на возврат?"}
```

Ответ адаптера завершает именно этот ход:

```jsonl
{"v":2,"type":"assistant","turn":1,"text":"В течение 14 дней."}
```

Для вызова хостового инструмента отправьте `tool_call` с уникальным `id`,
`name` из `hello.tools` и объектом `arguments`. Хост вернёт `tool_result`
с тем же `id`, `name`, строкой `text` и флагом `isError`; после обработки
результата отправьте `assistant`. На `cancel` завершите процесс. Любая
диагностика идёт в stderr, каждая JSONL-строка в stdout должна быть сброшена
из буфера. [Версии и учёт usage](command-protocol.md).
