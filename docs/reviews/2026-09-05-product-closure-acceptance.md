Этот отчёт отделяет исправленные дефекты, проверенный механизм и измеренное
качество конкретного агента. Он не объявляет продукт идеальным.

## Живая приёмка

Данные синтетические, ответы и изменения промпта не сценарные. Взяты исходники
поставляемого Python-агента поддержки «Волна» с **неизменённым system prompt**.
Автор — Claude Sonnet 4.6, Target — Qwen 3.5 9B. Проверки используют настоящий
`kb_search`, `get_account`, `create_ticket` и отдельное состояние каждого кейса.

Точный каталог первой попытки: `.ahde/live-pilots/python-grCGi9`.
Исходный замер: 8/12 pass, 4 fail, 0 execution errors. Автоцикл разделил корзину
на 7 authoring и 5 validation кейсов и предложил два разных изменения только
`prompts/system.md`. На validation в двух повторах исходный агент прошёл 6/10,
первый вариант — 8/10 с неубедительным интервалом, второй — 10/10 с каноническим
verdict `improved`. Выбран второй вариант; исходный checkout остался неизменным.

Отдельный экзамен завершён: **10/30 → 21/30** успешных прогонов на 15 кейсах
в двух повторах. Строгая проверка чисел и явных ссылок сохраняет эти же 10/30
и 21/30. Девять прогонов выбранного варианта всё ещё не прошли. Из 15 кейсов
семь улучшились, один регрессировал. Общий средний балл вырос на 8,8 п.п., но
его 95% интервал **−0,7…+18,5 п.п.** пересекает ноль. Канонический sealed verdict
— `pass / no-regression`; надёжное улучшение общего балла этот экзамен не доказал.
Выпуск не выполнялся, исходная ветка не изменена.

При повторном validation общий pass был 10/10, а строгий аудит — 9/10:
один ответ прошёл `cites_source` по совпадению текста без явного source ID.
Исходный validation после такого же аудита — 5/10 вместо 6/10. Это важное
ограничение инструмента измерения, а не исправление задним числом артефактов.
Первый общий baseline после строгого аудита — 7/12 вместо 8/12.

Сохранены 179 RunRecord: 178 завершённых и один с ошибкой при остановке по
времени. 152 входят в 13 завершённых EvalRun; оставшиеся 27 принадлежат
незавершённому экзамену и не превращены в успешную оценку. Во всех попытках —
11 запросов к автору, 390 запросов Python-агента к модели. Сообщённая стоимость
— **$0,16004333**; ещё **$0,0005587** остаётся консервативным резервом одного
прерванного запроса с неизвестной стоимостью. Это квитанции API и оценка резерва,
не счёт провайдера.

Артефакты: `results.json`, `attempt-1.json`, `attempt-2.json`, `strict-audit.json`
в указанном каталоге. Финальный кандидат:
`candidate-f0a73cab-75be-4e6d-bb5b-e1c4d5414858`.
Sealed baseline: `erun_mtol7h9hft9evy`; выбранный вариант:
`erun_mtoluerwmhg2i4`. Аудит читает завершённые оценки, а прерванные записи
сохраняются отдельно. Никакая из попыток не удалялась.

Первая попытка остановлена ограничителем времени в ходе sealed exam; результат
экзамена не принят. Попытка сохранена в `attempt-1.json`. Восстановление обнаружило
дефект перехода: abandoned release candidate продолжал скрывать исходную
измеренную гипотезу. `releaseLineages` теперь исключает только попытки с проверенной
квитанцией abandonment; активная или законченная release lineage по-прежнему
блокирует альтернативы. Вторая попытка не вызвала модель и сохранена в
`attempt-2.json`; третья проверяет прежний exact diff и прежние кейсы без нового
авторства. Суммарный бюджет и все квитанции сохранены между попытками.

Первый driver использовал `output_contains` для чисел и `cites_source`, который
допускает совпадение текста вместо явной ссылки. Независимый offline audit
перепроверяет эти ответы по точным числовым границам и явным source ID. Канонические
записи не изменяются. В повторяемом driver новые корзины сразу требуют этих более
строгих условий; уже начатая приёмка не меняет инструмент измерения посреди опыта.

## Общая проверка

- Полный `npm run check` после исправления восстановления экзамена:
  **2487 passed, 3 skipped, 155 files**. Пропуски относятся к Docker на локальной
  машине. Лог: `.ahde/closure-release-final-check.log`.
- `npm run verify:package`: установка и запуск собранного пакета прошли.
- `demo:pilot`: 70 реальных Python-исполнений со сценарным локальным API;
  экспорт включает провалы и состояния мира.
- `demo:models`: 90 сравнительных исполнений и 15 нового baseline.
- `demo`: предложение → оценка → sealed gate → человеческое решение → adoption
  → следующий цикл.
- Восстановление прерванного экзамена: два focused-сценария, оба TypeScript
  check и последующий полный прогон прошли. Активная и завершённая проверка
  всё ещё закрывают повторное открытие; abandonment требует свежего согласия.
- CI точного коммита проверяется после публикации ветки; workflow `ci`
  запускает macOS и Linux, включая обязательный Docker на Linux.

## Границы результата

- Незнакомый пользователь ещё не проходил сценарий самостоятельно. Проверка
  модели и браузера не заменяет исследование удобства.
- Для приёмки на клиентском агенте нужны его исходники и тестовая корзина.
  Они не были переданы в этой итерации.
- Маленькая синтетическая выборка и выбор лучшего из вариантов не доказывают
  универсальное улучшение. Отрицательные и неубедительные результаты сохраняются.
- Для старого Spec с нестандартным расположением хранилищ требуется явный
  текущий `stateRoot`; поиска по диску и чтения прежней копии нет.
- Первое наблюдение на старте описывает записанный результат этой версии.
  Оно не обещает тот же ответ при новом запуске. Большие оценки остаются доступны
  через обычный просмотр, но не загружаются ради стартовой карточки.
