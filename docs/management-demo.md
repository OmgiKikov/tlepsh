# AHDE: демонстрация для руководства

AHDE помогает создать или подключить агента, найти его ошибки, подготовить исправление и проверить, что изменилось. Работа идёт в терминальном разговоре. Результат подкреплён конкретными диалогами, проверками, версией файлов и сведениями о цене и неопределённости.

Локальная приёмка 5 сентября 2026: 2 298 тестов прошли, 3 Docker-зависимых теста пропущены; установка пакета и полный сценарный цикл завершились успешно. Готовый [демонстрационный отчёт](../.ahde/management-demo/exports/version-v0.2.0.html) сохранён в этом checkout вместе с паспортом и dataset. Эти локальные артефакты не входят в Git; `npm run demo` создаёт новые.

## Что показывать

| Момент | Действие человека | Что должно быть видно |
|---|---|---|
| Задача | «Сделай агента поддержки: он отвечает по нашей базе знаний и не придумывает условия возврата» | Короткое понимание задачи, существенные неизвестные, подготовленные инструкции и кейсы |
| Проверка | «Проверь его на обычных и сложных обращениях» | Что запущено, ход работы, результат и конкретная ошибка |
| Управление | «Останови. Сначала разберём ошибку с возвратом» | Остановка общей задачи; уже сохранённые результаты остаются; новое направление учитывается |
| Улучшение | «Подготовь исправление и проверь его» | Гипотеза, точная правка на рассмотрение, затем сопоставимая проверка принятой правки |
| Доказательства | Открыть ссылку Evidence | Настоящие ответы до/после, выполненные действия, причины вердиктов, видимые ухудшения и исключённые прогоны |
| Решение | «Принимаю эту версию» | Подтверждение точной версии и ветки; принятие, паспорт и начало следующего цикла |
| Возврат | Закрыть и снова открыть `ahde` | Продолжение беседы этого проекта, фактическое состояние файлов и понятный следующий шаг |

Подсказки формулировок — пример сценария. Кнопки подтверждения принадлежат хосту. Модель не может выдать себя за человека, прочитать закрытый экзамен или автоматически принять релиз.

## Воспроизводимая демонстрация без расходов

В установленном checkout:

```sh
npm run demo
```

Сценарий создаёт временный проект. Агент сначала неправильно называет срок возврата — 7 дней. Исправление заставляет его искать утверждённую политику и ссылаться на источник. Затем выполняются сравнение, закрытая проверка, принятие версии и переход к следующему циклу. Команда сохраняет HTML-отчёт, паспорт, диалоги и исходные доказательства и печатает их пути.

**Модель в этой демонстрации сценарная.** Прогоны, Git, проверки, артефакты и переходы настоящие. Этот сценарий подтверждает работу механизма; понимание произвольной просьбы и качество реальной модели оцениваются отдельно.

Для целевой проверки терминального пути:

```sh
npm run acceptance:guided
```

Здесь проверяются настоящие обработчики событий расширения, состояние фоновой задачи, остановка, доставка результата, свежий контекст, точное принятие и сквозной цикл с локальными модельными ответами. Общий `npm run check` включает эти же тесты, а также восстановление Workshop и истории разговора.

## Как читать результат

- Изменение считается применённым только после соответствующего записанного решения. Подготовленный diff ещё не меняет действующего агента.
- Процент успешных задач, изменение среднего балла и доверительный интервал отвечают на разные вопросы. Маленькая выборка остаётся маленькой даже при красивом результате.
- Закрытая проверка сравнивает две версии. Её `pass` сам по себе не устанавливает абсолютную готовность агента к работе с клиентами.
- Ошибка инфраструктуры не становится успехом, неуспехом или улучшением поведения агента. Несопоставимые условия явно запрещают вывод об улучшении.
- Выполненный вызов инструмента и ссылка на документ — конкретные наблюдения. Для правильного бизнес-результата нужны соответствующие проверки состояния и содержания ответа.
- Отсутствующий расход и неполные суммы показываются как неизвестные. Существующий формат judge/simulated-user записей ещё допускает ноль при отсутствии тарифов: точность этой части стоимости без заданных тарифов не подтверждена.

## Основание показа и дальнейшая приёмка

[Единый план реализации](plans/2026-09-05-guided-flow-implementation.md) содержит результаты трёх независимых review и фактический журнал проверок. [Ранее выполненная приёмка на реальных моделях](reviews/2026-09-05-live-improvement-acceptance.md) сохраняет успешные и неуспешные попытки; она не является новым прогоном текущего терминального интерфейса.

Перед внешним запуском нужен пилот с незнакомым оператором и реальными задачами: время до первого полезного результата, число вмешательств, расходы и качество на независимых случаях. Зелёная локальная сборка также не заменяет результат Linux/Docker CI. Облачный интерфейс, управление командой и развёртывание не входят в этот срез.
