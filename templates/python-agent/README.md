# Агент поддержки провайдера — на Python

Шаблон для случая, когда агент у вас уже есть и написан не на Pi, а обычной
программой. AHDE запускает `agent.py` как дочерний процесс и разговаривает с
ним по протоколу v2 — по одной строке JSON в каждую сторону.

## Что здесь лежит

| Файл | Зачем |
|---|---|
| `agent.py` | Сам агент. Стандартная библиотека, никаких зависимостей. |
| `prompts/system.md` | **Правила поведения. Это и есть editable surface.** |
| `tools/*.tool.yaml`, `bin/*` | Инструменты. Запускает их хост, в песочнице. |
| `data/kb/*.md` | Справочные документы, объявленные в `manifest.data`. |
| `evals/development.jsonl` | 8 стартовых кейсов: справка, поиск по абоненту, фиксированная история, два реактивных диалога. |
| `http_bridge.py` | Если агент уже живёт за HTTP (Langflow, n8n, свой сервис). |
| `function_bridge.py` | Если агент — Python-функция `respond(text)`, возвращающая строку. |

Документы доступны через объявленный хостом `kb_search`. Поиск выполняется
по замороженному BM25-индексу конкретного прогона; весь корпус не вклеивается
в системный промпт. В трассе остаются запрос, найденные фрагменты и ссылки
ответа. Это локальный retrieval, а не эмуляция реального embedding-сервиса:
для проверки клиентского векторного поиска нужен его отдельный адаптер.

## С чего начать

```sh
ahde            # первый диалог спросит модель агента, судьи и симулятора
```

Заглушки `replace-with-model-id` в `manifest.yaml` править руками не нужно:
AHDE запишет выбранные модели отдельным ревьюируемым коммитом. Ключи он берёт
из переменных окружения по имени (`AHDE_MODEL_API_KEY` и соседние) — сами
значения не попадают ни в манифест, ни в улики.

## Что правит цикл улучшения

`manifest.yaml` объявляет `harness.files: [prompts/**]`. Это значит, что
предложения Билдера могут менять только системный промпт: программа-агент
остаётся вашей. Если поведение агента задаётся не промптом, а конфигом —
поменяйте этот список, и цикл будет править то, что вы назвали.

## Мир кейса

Кейс может описать состояние, в котором он происходит:

```json
{"id": "...", "input": "Договор 4412, какой тариф?",
 "world": {"state": {"accounts": {"4412": {"tariff": "Скоростной", "monthly": 800}}}}}
```

Хост кладёт путь к этому состоянию в `AHDE_WORLD`; `bin/get_account` читает
его, `bin/create_ticket` дописывает в него заявку. Один и тот же вопрос в
разных мирах — два разных кейса, и хеш датасета это различает.

## Сценарий пользователя

`technician-ticket` задаёт **скриптовую историю** через `messages`. Последняя
реплика повторяет `input`; агент отвечает один раз. Предыдущая реплика
ассистента задана автором, а не получена от проверяемого агента. Такой кейс
проверяет следующий ответ, но не доказывает, что агент сам задал нужный вопрос.

`vague-complaint` задаёт **реактивного пользователя** через `simulatedUser`.
`input` остаётся фиксированной первой репликой; отдельная модель пишет
следующие реплики по ответам агента. `messages` и `simulatedUser` несовместимы.

```json
{"goal": "Добиться заявки на мастера",
 "persona": "Пишет коротко, детали сообщает в ответ на вопросы",
 "knownFacts": "Мой договор 3050. Вижу оборванный кабель. Перезагрузка роутера не помогла.",
 "maxTurns": 4,
 "stopWhen": "агент сообщил номер созданной заявки"}
```

`knownFacts` содержит только то, что человек знает **до** разговора: свой
номер договора, наблюдения, уже выполненные действия. Это необязательная
строка до 8 КиБ UTF-8. Старые кейсы с фактами в `goal`/`persona` читаются без
миграции. Для импорта из таблицы есть `simulatedUser.knownFactsColumn` в рецепте;
пустая ячейка означает отсутствие дополнительных фактов.

В `angry-about-money` человек знает договор `9002`, но не баланс и не причину
блокировки. Они лежат только в `world.state`, откуда их читает `get_account`.
Не копируйте в `knownFacts` весь backend, эталон `expected`, `world.expect` или
критерии проверки. Неизвестное остаётся неизвестным; симулятору предписано не
выдумывать ответ и не соглашаться с подсказкой агента вопреки своим фактам.

В реактивном кейсе с мастером `tickets: []` меняется только инструментом
`create_ticket`. Условие `stopWhen` означает, что пользователь услышал номер,
а не что заявка действительно создана. Это независимо проверяют
`world.expect` (договор и статус заявки) и `tool_called`.

Все данные этих примеров вымышлены для сценария. При генерации своих кейсов
отмечайте такие допущения в `coverageNotes`; неизвестные бизнес-правила туда
же записывайте вопросами, а не придумывайте для них оцениваемый эталон.

**Пределы симулятора:** он читает только цель, роль, известные факты, условие
остановки, лимит ходов и ограниченный текст диалога. Он не видит инструменты
или скрытый мир и не проверяет истинность слов агента. `maxTurns` ограничивает
число ответов агента (1..12), а не качество результата. Температура 0 снижает
вариативность, но не гарантирует повторяемость. Инструкции не исключают
выдумки и излишнюю уступчивость модели: просматривайте трассу и обмены
`user/<turn>.json`. Эти кейсы не доказывают поведение реальных людей или
превосходство реактивных тестов над скриптовыми.

## Свой агент вместо этого

Для существующей синхронной или `async`-функции `respond(text) -> str` положите
её модуль рядом с `function_bridge.py` и выберите команду:

```yaml
execution:
  kind: command
  command:
    argv: [python3, function_bridge.py, my_agent:respond]
    protocolVersion: 2
```

Мост не меняет вашу функцию. Её `print` остаются диагностикой, ответ — только
возвращённая строка. Каждый кейс запускает отдельный процесс; внутри диалога
процесс сохраняется между репликами. Используйте `if __name__ == "__main__"`
для интерактивного запуска вашего модуля, чтобы импорт не запускал CLI.
Мост не знает внутренних вызовов инструментов и расходов: они остаются
неизвестными. Для состояния мира и инструментов, исполняемых хостом,
используйте полный протокол, как в `agent.py`.

Для собственной программы-адаптера оставьте `manifest.yaml`, `evals/` и
`tools/`, замените `agent.py` своим и поменяйте `execution.command.argv`:

1. Читать строки JSON из stdin, писать строки JSON в stdout, каждая с `"v": 2`
   (та же версия, что в `execution.command.protocolVersion`).
2. Отвечать на `user` сообщением `assistant` — оно заканчивает ход.
3. Ничего постороннего в stdout. Диагностика — в stderr.

Всё остальное — инструменты, расход токенов, мир — необязательно.

## Сеть из песочницы

Агент ходит к эндпоинту сам, поэтому в манифесте `network: allow`. Хост
разрешает песочнице route-сокет, чтобы `getaddrinfo` ставил IPv4-адреса
первыми на машине без глобального IPv6; `agent.py` дополнительно сортирует
адреса сам (`prefer_ipv4`) — иначе один запрос висел бы ~75 с в `SYN_SENT`.
Если пишете свой агент, сделайте то же или задайте короткий таймаут коннекта.
